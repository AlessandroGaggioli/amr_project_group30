## General Recommendations 

In addition to the standard nodes/launch files to execute, we expect to have 3 launch files to launch each of the 3 tasks. 

Some general recommendations for the project implementation: 

The use of non-standard/questionable procedures will be negatively evaluated, e.g. calling ROS topic or services as subprocesses within another node. Please use ROS functionalities as they are intended to be used (publishers/subscribers, service clients/servers..); The robot clearly missing the cube during grasping or dropping it outside the place location will be negatively evaluated; The gripper closing/opening procedure must be clearly visible during the simulation; It is possible to use the Link Attacher pluging to facilitate the grasping procedure BUT reasoneable alignment between the end-effector and the cube must be performed; Trying to avoid the use of the plugin will be positively evaluated (e.g. modifying the simulation friction, etc..); The use of hardcoded positions for pick and place will be negatively evaluated; The robot must be able to autonomously discover the pick and place locations by exploiting the aruco markers;

## FAQ 

After a CTRL+C on a ROS2 launch command, the gazebo simulation may fail to exit properly. This may cause unexpected behaviors if we try to launch the simulation again. 

To verify if the simulation is still running, we can use the following command: 

ps -ef | grep ros 

If the simulation is still appended to the process list, you will see an output similar to the following: 

student 12433 11844 0 14:05 pts/2 00:00:01 /usr/bin/python3 /opt/ros/humble/bin/ros2 launch tiago_gazebo tiago_gazebo.launch.py 

To kill the process, you can use the following command: 

sudo kill -9 12433
